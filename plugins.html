Plugins

Extend DraconDex with a link

A plugin is a git repository with a manifest. Paste its link into the app, look at what it says it will do, and confirm. Each plugin gets its own database tables and runs in a separate sandboxed window — it cannot read your novel data.

Installing

Four steps, one link

Requires DraconDex 4.2.0 or newer.

  1. Open Settings → Plugins in DraconDex.
  2. Paste the repository link into the single field. A bare owner/repo, an HTTPS URL, an SSH URL or a /tree/<branch> link all work. GitHub and GitLab are supported; other hosts are rejected.
  3. Read the preview. The app fetches the manifest and shows the plugin's name and version, every file it will download, every table it will create, and every host it may talk to. The preview touches neither disk nor database.
  4. Confirm. The installer resolves and validates everything again from scratch — it does not trust the preview — then writes the files and creates the tables.
Plugins are code from the internet. The sandbox keeps a plugin out of your novel data and off any host it did not declare, but it cannot make a badly-written or hostile plugin safe. The app's PLUGINS.md has an honest section on what the sandbox does and does not protect against — worth reading before you install anything you did not write.

The sandbox

What a plugin can and cannot reach

It can

  • Read and write its own tables through window.pluginApi.table.*
  • Call hosts it declared in permissions.net — HTTPS only, with Cookie, Host, Origin and Referer stripped and no cookie jar
  • Stream responses, and run an OAuth 2.0 + PKCE flow that opens the system browser
  • Render as a panel docked in the main window, and ask for the open module's id, name and kind if it declared permissions.context

It cannot

  • Touch window.api — the main app's IPC surface is simply not present in a plugin window
  • Read your characters, notes, timelines, or any other app table
  • Reach a host it did not declare, downgrade to plain http:// (except a loopback address with an explicit port), or follow a redirect off its allowlist
  • Widen what it asked for after install — the installer re-validates the manifest itself and ignores the preview

Plugin windows run with contextIsolation: true, nodeIntegration: false and sandbox: true. Table and column names from a manifest are checked against strict regex whitelists before they are ever composed into SQL — no identifier from a plugin reaches the database unchecked.

Build your own

A plugin is one JSON file and some HTML

Put dracondex-plugin.json at the root of a public repository. Fork DraconDex-Plugin-Template to skip the boilerplate. 

{
  "id": "myplugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "entry": "index.html",
  "files": ["index.html", "panel.html", "app.js"],
  "panels": [
    { "id": "chat", "title": "My Chat", "icon": "💬", "entry": "panel.html" }
  ],
  "permissions": {
    "net": ["https://api.example.com"],
    "context": ["module"]
  },
  "tables": [
    { "name": "notes", "columns": [
      { "name": "title", "type": "TEXT" },
      { "name": "rating", "type": "INTEGER" }
    ]}
  ]
}

The limits

Field Rule
id Lowercase a–z, 0–9 and _; 20 characters max
entry An HTML file, and it must also appear in files
files Up to 30 files, 2 MB each. The app fetches exactly these — it never walks the repository
tables Up to 10 tables, 25 columns each. Column types are TEXT, INTEGER or REAL only — no defaults, checks or foreign keys
panels Up to 5. Each needs a unique id, a title of 40 characters or fewer, and an entry listed in files
permissions.net Up to 10 bare https:// origins — no path, query or credentials. The one exception is a loopback address with an explicit port, e.g. http://localhost:11434
permissions.context Only "module" today — the open module's identity, never its content
Panels get reloaded. A docked panel is re-rendered whenever the main window re-renders, so keep state in your own tables and restore it on load — never in a plain variable.
